# CALQS 新商品LP構成案ライティングスキル

このスキルは、CALQS（カルクス）ブランドの新商品に対して、LP（ランディングページ）構成案を作成する。
構成案は、デザイナーへの指示書として機能するもので、テキスト＋画像指示の形式でNotionページに出力する。

## 重要な前提

- このスキルは「5ステップ」で進む。**1ステップずつユーザーの確認を得ながら進めること**。一気に最終成果物まで進まない。
- 構成案の質を決めるのは「テンプレートの正確さ」ではなく、**「気づき」のクオリティ**と**その伝え方（流れと見出し）**。ステップ2とステップ3に最も力を注ぐこと。
- **Notionに書き込む前に、必ずチャットで見出しレベルの合意を取る**（ステップ3）。書いてから直すのは手戻りが大きい。
- 参考ファイル（生成前に必ず読む）
  - `references/insight-framework.md` … 「気づき」発明のフレームワーク（ステップ2）
  - `references/education-section-patterns.md` … 教育セクションの型・見出しルール・読みやすさルール（ステップ3・4）
  - `references/lp-structure-patterns.md` … LP全体の構造パターン（ステップ3・4）

---

## 共通ライティング原則（全ステップで守る）

この5原則は、過去に何度も差し戻しが発生したポイント。**書く前と書いたあとに必ずセルフチェックする**。

### 原則1：結論が先。説明はあと
セクションの冒頭は必ず「言い切りの結論」から始める。前振り・伏線・順を追った説明から入らない。
結論を出したあとに「なぜなら」を並べる。

### 原則2：見出しは「主張」であって「説明」ではない
- ❌「② では、なぜ髪は変わらないのでしょうか」（説明的・何も言っていない）
- ⭕「そのシルクの枕カバー、2日目からは"別の布"です」（言い切り・気になる）
- 見出しだけを縦に読んで、話の骨子が伝わるか確認する。伝わらなければ見出しが弱い。

### 原則3：難しい話は、身近な体験に翻訳する
専門用語（帯電列、ケラチン、フィブロイン、遊離脂肪酸…）をそのまま本文に置かない。
- 読者が**毎日体験していること**に置き換える（例：皮脂で滑らなくなるスマホ画面／ベタつく換気扇の油汚れ）
- 数値やエビデンスは**本文ではなく括弧書き・注釈**に降ろす
- 「長く書く」こと自体は悪くない。**意味の分からない話が長い**のがダメ。

### 原則4：箇条書きの粒度をそろえる（MECE）
「理由は3つ」と並べるとき、**1つの話を2つに割らない**。
- ❌ 理由1「膜ができる」／理由2「その膜がベタつく」＝ 同じ1つの話の前半と後半
- ⭕ 分けるなら要素で分ける：「皮脂」「ヘアオイル」「スキンケアの油分」＝ 3つ
- 並べたあと「これは本当に別々の理由か？」と自問する。

### 原則5：教育セクションを変えたら、以降も必ず作り直す
ポイント紹介・レビュー・クロージングは、**教育セクションで提示した問題への答え**として書かれている。
教育セクションの流れや用語を変更したら、以降のセクションのリード文・順番・参照語を**必ず整合させる**。
（例：教育セクションが「摩擦／帯電／菌」の3つになったら、ポイント紹介のリード文も〈「摩擦」への答え〉の形に揃える）

## ステップ0：既存資産の調査

ヒアリングの前に、社内にすでにある材料を必ず確認する。ここを飛ばすと、既知の課題を踏む。

1. **既存LPがあれば必ず中身を読む**
   - CALQSのLPは**ほぼ全編が画像**であることが多い。HTMLからテキストが取れなくても諦めない。
   - ページのHTMLを取得 → 画像URLを抽出 → 画像をダウンロード → **画像として読み込んで**構成を書き起こす。
   - 書き起こしたら「現行LPの構成一覧」と「構造的な弱点」をユーザーに提示する。
2. **社内メモ・議事録（Notion）があれば読む**
   - 「今のLPについて思うこと」「やりたい試験」などに、次のLPの正解が書かれていることが多い。
   - 未確定の試験・撮影は、構成案側に**差し込み枠（★）**として先に用意しておく。
3. 調査結果は箇条書きで要約してユーザーに共有してから、ステップ1へ進む。

---

## ステップ1：商品情報のヒアリング（3ラウンド制）

ユーザーから商品情報を受け取ったら、うのみにせず**3ラウンドに分けて深掘り**する。
目的は、構成案のクオリティを左右する「暗黙知」を引き出すこと。

### ラウンド1：事実の収集

以下の情報を確認・収集する。ユーザーが既に提供済みの情報はスキップしてよい。

- 商品名（正式名称 + ブランド名 CALQS）
- 商品カテゴリ（枕 / マットレス / サポーター / その他）
- ターゲット層（年齢層、性別、職業傾向、どんな悩みを持つ人か）
- 差別化ポイント（主要な機能や特徴。3〜4個）
- 温熱機能の有無と詳細（温度設定、温め箇所など）
- 素材・構造情報（層構成、中材、サイズ、高さ調整など）
- スペック（温度設定、タイマー、電源、消費電力など）
- 価格（バリエーション含む）
- 販売実績やメディア掲載があれば
- 既存LPや写真素材のURLがあれば
- トンマナの希望（上品系 / カジュアル系 / 元気系 etc.）

不明な項目は「未定」でもOK。★で仮置きして進められることを伝える。

### ラウンド2：開発者の意図の深掘り

ラウンド1の情報を踏まえて、以下のような質問で暗黙知を引き出す。
全部聞く必要はない。商品に応じて適切なものを3〜5問選んで聞く。

- 「なぜこの素材・構造を選んだのですか？他の選択肢と比べてどう違いますか？」
- 「開発中に一番こだわったポイントは何ですか？」
- 「他社の同ジャンル商品を使った人が不満に思いがちなことは？」
- 「この商品を使って一番喜んでもらいたいのはどんなシーン？」
- 「"これだけは絶対伝えたい"ということは何ですか？」
- 「実際に使ってみて、想定外に良かった点はありますか？」
- 「自社の他の商品（ホッとする枕PLUSなど）との違いや関係性は？」

### ラウンド3：ターゲットの生活を想像する質問

構成案の「悩み共感セクション」と「レビュー」のリアリティを高めるための質問。
2〜3問で十分。

- 「この商品を買う人は、普段どんな1日を過ごしていますか？」
- 「寝る前にどんなことを感じていそうですか？」
- 「今まで何を試して、何がダメだったと感じていそうですか？」
- 「どんなレビューが書かれると嬉しいですか？」

### ヒアリングの進め方ルール

- **「わからん」と言われた項目は深追いしない。** 仮説を立てて「★仮」と明記し、先に進む。
  ユーザーが答えられないのは、まだ決まっていないか、考える必要がないと判断しているサイン。
- **質問は1回のメッセージにまとめる。** 1問ずつ往復しない。
- **ヒアリングと並行して、裏付けのWeb調査を進めてよい。** 待たせない。
- 3ラウンドが終わったら、**収集した情報を箇条書きで要約**してユーザーに見せ、抜け漏れがないか確認する。

## ステップ2：「気づき」の発明とアイデア選択

ここがLP構成案の質を決める最も重要なステップ。

### 手順

1. `references/insight-framework.md` を読む
2. ステップ0〜1で得た情報を元に、**4つの角度（A〜D）**から「気づき」のアイデアを**最低3パターン、できれば5パターン**提案する
3. 必要に応じて、Web検索で科学的・医学的な根拠を調査して補強する

### 提案フォーマット

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━
【案1】
【角度】（A: 原因のメカニズム / B: 常識の逆転 / C: 行動と結果の因果 / D: 比較優位）
【世の中の認識】世の中の人がこう思っていること
【提案する気づき】実はこうである
【納得感の根拠】なぜこの気づきに説得力があるのか
【構成案での使い方】LP上でどう展開するか
━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

### 提案時の心得

- 「なるほど！確かに！それは納得」と思える内容であること。眉唾系は絶対にNG。
- 根拠がネット検索で否定されるようなものは出さない。
- 角度が偏らないようにする（全部が「メカニズム型」だけ、などは避ける）。
- メインの気づき1つ + サブの気づき1〜2つ、という使い方もあるので、組み合わせ提案もOK。
- **推しの案を1つ明示する。** 並べるだけでなく「これを軸にすべき」と言い切る。

### ユーザーの選択を待つ

提案したら、ユーザーに「どれが良いですか？組み合わせもOKです」と聞く。
選択されたら、ステップ3に進む。

## ステップ3：教育セクションの設計と、全見出しの確認（Notionに書く前）

**このステップが、本スキルで最も差し戻しが起きやすい箇所。**
本文を書く前に、`references/education-section-patterns.md` を読み、**チャット上で**以下を提示して合意を取る。

### 3-1. 教育セクションの設計（標準の型）

教育セクションは、原則この型で組む。

```
【結論】   言い切りの1〜2行。LP全体で一番大きく見せる見出し。
           ＋ 直後に「誰もが知っている身近な例」で即納得させる
【理由】   なぜその結論になるのかを、箇条書きで先に提示（3つ前後・粒度をそろえる）
【個別解説】箇条書きの1つ1つを、順に説明（各ブロックも結論見出し→説明）
【だから】 「だから◯◯が必要」という、商品の必要性に着地する一文
```

- 悩み共感セクションの最後の一文（例：「実は、◯◯を使えばいいというわけではないんです」）を**受けて始める**こと。
- 各ブロックの見出しは、原則1〜2行。**見出しだけ並べて意味が通るか**を必ず確認する。
- 長さの目安：結論＋理由リスト＋解説3つ＋着地 ＝ 6〜8ブロック。10ブロックを超えたら削る。

### 3-2. 提示するもの

1. 教育セクションの**全見出し案**（上の型に沿った並び）
2. 各見出しの下に、本文の要旨を1〜2行だけ
3. FV・悩み共感・ポイント紹介・レビュー・価格までの**全体アウトライン**（見出しレベル）

### アウトライン提示の形式

```
■ FV（ファーストビュー）
　キャッチコピー案：「〇〇〇〇」（別案も2つ出す）
　サブコピー案：「〇〇〇〇」

■ 悩み共感セクション
　- 悩み1／悩み2／悩み3
　- 締めの一文：「実は、〇〇というわけではないんです」

■ 気づきの教育セクション
　【結論】「〇〇〇〇」
　【理由】1. 〇〇 ／ 2. 〇〇 ／ 3. 〇〇
　【個別解説】各1行
　【だから】「だから〇〇が必要です」

■ ポイント紹介（3〜6個）
　ポイントN：見出し案「〇〇」／〈「◯◯」への答え〉

■ 信頼構築セクション ／ ■ ユーザーの声 ／ ■ スペック・価格
```

### ユーザーの承認を待つ

「この見出し・この流れで本文を書きます。方向性はOKですか？」と確認する。
**OKが出るまでNotionには書き込まない。** 見出しの語感レベルの指摘は、この段階で回収する。

## ステップ4：構成案の本文生成とNotion出力

`references/lp-structure-patterns.md` と `references/education-section-patterns.md` を参照しながら、Notionページとして構成案を出力する。

### 出力形式

- Notionページとして作成する（ユーザーが指定した場所、または田代メモの下）
- テキストはNotionのマークダウン形式で記述
- 画像が入る箇所は「★画像★」で示し、下に「└画像の内容・目的」を説明
- 未確定の情報は「？？？」で仮置き
- デザイナーへのメモは「※」で記述。**メモは1ブロックにつき1つまで**（メモだらけにしない）

### 本文の書き方ガイド

**FVセクション：**
- キャッチコピーは短く（1〜2行）。体の悩みと解決策を凝縮。
- `<br>`で改行を入れてスマホ表示を意識。

**悩み共感セクション：**
- 3〜5個の悩みを列挙。具体的な症状 + 生活シーンの組み合わせ。
- 最後は「実は、◯◯というわけではないんです…！」の形で教育セクションへ橋渡しする。

**気づきの教育セクション：**
- ステップ3で合意した型（結論 → 理由の箇条書き → 個別解説 → だから）をそのまま展開する。
- コラムを入れる場合は「コラム：〇〇とは？」の見出しで、本文の流れを止めない位置に。

**ポイント紹介：**
- 各ポイントの構造：
  ```
  ポイントN
  小見出し（短い説明）
  ## メイン見出しコピー（太字・大きめ）
  ★画像★
  　└画像の説明
  〈「◯◯」への答え〉…教育セクションのどの問題に答えているかを最初の1文で明示
  詳細説明テキスト
  ```
- **並び順は、教育セクションの着地から自然につながる順にする。**
  （例：「1枚では無理」で着地したなら、次は枚数の話 → そのあと素材の話）

**レビューセクション：**
- 3〜5件。年代・性別・職業付き。
- 太字の一言見出し + 詳細な体験談の形式。
- ユーザーが「取りたい声」を指定していれば、**その言葉がレビューの見出しに入る**ようにする。
- 実レビューがない場合は「仮レビュー」と明記する。

**スペック・価格：**
- 分かっている情報を記載。未定は「？？？」。
- 既存LPの価格表記に誤解を招く箇所があれば、修正案として明記する。

### 出力後の自己チェック（必須）

Notionに書いたあと、以下を確認してから報告する。

- [ ] 見出しだけを縦に読んで、話の骨子が伝わるか
- [ ] 専門用語がそのまま本文に残っていないか
- [ ] 箇条書きの粒度がそろっているか（1つの話を2つに割っていないか）
- [ ] ポイント紹介・レビューが、教育セクションの内容と整合しているか
- [ ] 薬機法NG表現（治る・改善する・抜け毛が減る 等）が入っていないか

### Notion編集時の実務ルール

- **ユーザーがページを直接編集している前提で動く。** 更新の直前に必ずfetchして、最新の本文を取得してから置換する。
- `update_content` は**完全一致**でしか置換できない。長文を一括置換するより、**見出し単位の小さな置換を複数**に分けるほうが失敗しにくい。
- 置換に失敗した場合は、勝手にリトライせず、fetchし直して現在の本文に当て直す。

### 出力完了後

「構成案を作成しました。確認して、修正したい箇所があれば教えてください」と伝え、**変更点の要約をチャットにも書く**（Notionを開かなくても差分が分かるように）。

---

## 注意事項

- 各ステップの間で必ずユーザーの確認・承認を得ること。勝手に次のステップに進まない。
- 「気づき」は構成案の核心。ステップ2では時間をかけて考え、安易なパターンに逃げない。
- 薬機法に抵触する表現（「治る」「改善する」など）は避ける。「〜と言われています」「〜が期待できます」等の表現を使う。
- CALQS商品の温熱機能は「遠赤外線（グラフェンシート）」が多い。この技術的特徴は差別化の武器なので、該当する場合は構成に組み込む。
- 画像指示は具体的に書く。「いい感じの画像」ではなく「温度設定のUIが分かるコントローラー画像」のように。
