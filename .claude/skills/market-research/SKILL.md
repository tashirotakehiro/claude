# マーケ調査チーム（判定は人間・AIは判断材料と成果物）

以下の商品についてマーケ調査を実施してください。
まず `.claude/skills/_shared/business-model.md`・`.claude/skills/_shared/notion-rules.md`・`.claude/skills/_shared/notion-template.md` を読むこと。

**商品情報:** $ARGUMENTS

**構造上の原則: Go/No-Go判定は必ず人間が行う。AIは判定を下さず、チャットでもNotionでも「Go/No-Go」を出力しない。AIの仕事は2つ — ①キル基準に対する証拠＝判断材料を集めて提示する ②成果物（コピー・LP構成等）を作る。判断材料は雰囲気の総合判断ではなく証拠で示す。**

**実行単位: このスキルは商品企画（product-planning）とは別のセッションで単体実行する。前提（アンカー定義・ジャッジメント判定・検証課題・商品案）はチャット履歴ではなく、ドシエと企画マスターページから読み込む。企画マスターページの「マーケ調査」トグル（1〜13）への記入は、このスキルだけが行う（商品企画セッションでは記入しない）。**

**商品案(初期)は不可侵: このスキル（マーケ調査系）は企画マスターページの「商品案(初期)」トグルを絶対に変更しない。商品案の更新は商品企画セッションの管轄。調査で商品案に関わる発見（仕様の示唆・懸念）があっても商品案には書かず、マーケ調査トグルとドシエの検証課題に書いて人間に提示する。**

## 出力スタイル（チャット報告・Notion書き込みとも厳守）
- 全セクション**箇条書き**で書く。長い段落・文章での説明は禁止
- 1項目1行を基本とし、どうしても必要な場合のみ2行まで
- 「結論 → 根拠」の順。前置き・言い回しの装飾は削る
- 比較・一覧は表を使う（競合、価格、シナリオ等）

実行前に必ず:
1. この企画の**ドシエ**（notion-rules.md参照）を読む。アンカー定義・ジャッジメントテスト判定（軸×判定×確信度）・検証課題をチャット要約ではなくドシエから取得する
2. notion-rules.md のルールに従いフィードバックログの直近30件を読み、過去の没/見送りパターンを判定基準に反映する

## フェーズA: 判断材料の収集（判定は人間が行う）

### 再審ルール（ジャッジメントテストとの役割分担。二重裁判をしない）
- ジャッジメントテストの軸×判定×確信度を**初期値として引き継ぐ**。確信度「高」の判定は、フェーズAで**新しい証拠**が出た場合のみ覆せる（＝再審）。同じ証拠で蒸し返さない
- 調査リソースの優先順位: ①グレー軸（検証課題）の解消 ②確信度「中/低」の軸の定量化 ③フェーズA固有の項目（競合価格帯・ターゲット量・ポジショニング・ペインポイント）
- 再審が発生した場合は「旧判定 → 新証拠 → 新判定」をドシエのジャッジメントテスト記録に追記する

3つのサブエージェント（Agentツール）を**並列で**起動する。
**起動時の必須事項**: サブエージェントはリーダーのコンテキストを共有しない。各エージェントのプロンプトに、ドシエから取得した**ジャッジメントテスト判定（軸×判定×確信度）**と**検証課題（グレー軸）**を必ず埋め込むこと。これを渡さないとエージェント3が攻撃対象を絞れず、際限なく調査して返ってこなくなる。

### エージェント1: 需要検証担当
- どんな悩み・課題を解決するか（統計データは**出典URL必須**。見つからなければ「未確認」と明記。捏造厳禁）
- ターゲット定義（性別・年齢・職業・ライフスタイル）と、ターゲット量の推測（検索ボリューム・市場データに加え、**市場実測シグナル**＝競合のレビュー増加速度→推定月販、広告の継続配信期間。business-model.md参照）
- **販売価格は提案しない**（価格は人が決める。business-model.md「価格の扱い」参照）。価格判断の材料は競合の価格・機能の実データ（エージェント2が担当）に委ねる

### エージェント2: 競合・レビュー分析担当
- **ベネフィット競合**を含む競合8商品以上（サプリ・アプリ・医療・施術など別カテゴリも。同じ悩みを解決する商品は全て競合）
- 各競合の価格・機能・レビュー評価・低評価レビューの不満点
- 主要競合の**レビュー増加速度→推定月間販売数**と、広告ライブラリでの**配信継続期間**（＝実際に売れている・広告が回っている証拠。机上の市場規模データより優先）
- ポジショニング分析、市場ギャップ、勝ち筋
- 顧客ペインポイントTOP5と、LP訴求に使える感情的キーワード集

### エージェント3: 悪魔の代弁者（No-Go専任）
- **この商品が売れない理由だけ**を証拠付きで構築する。Goの材料は一切探さない
- ただし再審ルールに従い、**ジャッジメントテストが確信度「高」で通過させた論点を同じ証拠で蒸し返さない**。攻めるのは ①グレー軸 ②確信度「中/低」の軸 ③ジャッジメントテストが見ていない新しい事実

**終了条件（これを守らないと収束せず返ってこない。厳守）:**
- **出力は反証3〜5本まで**（No-Goに効く強い順）。6本目以降は探さない。「もっと強い反証があるか」を無限に探さない
- **攻撃対象を固定する**: business-model.md の共通キル基準5項目 ＋ 起動プロンプトで渡されたグレー軸・確信度「中/低」の軸のみ。それ以外は対象外
- **1論点あたりWeb検索は1〜2回まで**。出典が見つからなければ「未確認（出典なし）」と明記して次へ進む（＝“売れない証明”を出典付きで固めようと沼らない。悪魔の証明を避ける）
- **出力フォーマット**（1反証1行の表）: `反証 | 該当キル基準/軸 | 証拠(URL or 未確認) | 深刻度(高/中/低)`
- 最後に「**最も致命的な反証1つ**」を明示して終える

### リーダー統合（あなたの仕事。判定はしない）
1. 3エージェントの結果を統合し、**統合サマリー**（商品概要・差別化ポイント・競合価格帯と競合の機能・懸念点）を書く。販売価格の提案・価格根拠は書かない（価格は人が決める）
2. **キル基準チェック表**を作る（ジャッジメントテストの判定を初期値とし、フェーズAで更新された軸だけ差分「旧判定 → 新証拠 → 新判定」を明示。更新のない軸は再掲のみ）
3. **判断材料の総括**を作る: 進めたい場合に効く材料 / 見送りに効く材料（悪魔の代弁者の反証含む）/ 残るリスク / どんな証拠が出れば見方が変わるか
4. **Go/No-Go判定は下さない・書かない**（判定は人間の仕事）。この時点で判断材料をユーザーにチャットで報告し、ユーザーの判定を待たずにフェーズBへ進む

## フェーズB: 成果物制作（判定に関わらず必ず実行）
1. この商品カテゴリの選び方（重要な仕様要素、★★★〜★で重要度）
2. バナーキャッチコピー案（5案以上、各30文字以内。直球/好奇心/Before After/数字/共感のタイプ別）
3. LPのFVとざっくり構成案
4. LP内容から逆算した商品仕様（必須★★★ / 試行錯誤★★ / あれば嬉しい★）
5. 収益試算（楽観/基本/悲観の3シナリオ。試算に使う価格は**競合価格帯からの仮置き**とし、仮置きであることを明記（販売価格の提案ではない — 価格は人が決める）。価格を変えた場合の感度も添える。年間3,000万円の達成条件を明示。CPC/CVRの仮定は市場実測シグナルで裏を取り、**裏の取れない定数だけの試算は「未検証」と明記**）

フェーズBは人間の判定を待たず、判断材料が悪くても必ず作る（省略しない）。見送りに効く材料が強い場合は、「何を変えれば再挑戦できるか（ピボット方向）」も判断材料の総括に添える。

## Notion書き込み（企画マスターページの「マーケ調査」トグル 1〜13）
書き込み先は企画マスターページ（プロジェクトDB）の「マーケ調査」トグル。欄と各出力の対応・書き込み手順（複製済みページの `<empty-block/>` を見出しごと一意に置換する等）は `notion-template.md` を単一仕様書として従う。テンプレの見出し文言・トグル・「└」記法を壊さない。
- ステータスは「新商品ｱｲﾃﾞｱ」のまま変更しない（notion-template.md 参照。任意で `date:マーケ調査開始日:start` を設定してよい）
- **フェーズA完了時点で 1〜5・7〜8 を先に書き込み**、フェーズB完了後に 9〜13 を追記する（notion-rules.md の分割ルール：1回3セクション程度・3〜5回）
  - 1商品概要 / 2流通商品との差別化 / 3悩み・課題 / 4ターゲット / 5ターゲット量 / 7懸念点 / 8他社類似商品 ← フェーズA。**6想定販売価格は記入しない**（価格は人が決める。競合の価格・機能は8に書く）
  - 9選び方 / 10バナーコピー / 11LPのFV・構成 / 12商品仕様（└必須/└＋α/└要議論の3ブロックに振り分け） ← フェーズB
  - 13マーケ担当的結論 ← **判断材料の総括**（進めたい場合に効く材料/見送りに効く材料・残るリスク・どんな証拠で見方が変わるか。**収益試算（年間3,000万円の達成条件）もここに織り込む**）。**Go/No-Go判定は書かない**（判定は人間が行い、人間が記入する）
- 「確定した商品概要」トグルのデモ内容（羽毛布団の表）は削除する。フェーズB④の必須/＋α/要議論をこの表に仮置きしてよい（確定は後工程の商品設計）
- **URL報告（毎回必須）**: フェーズA分・フェーズB分それぞれの書き込みが完了した直後に、企画マスターページのURLをチャットで送る（notion-rules.md「調査結果のURL報告」参照）
- 調査で解消・更新された**検証課題**は、ドシエ子ページの検証課題セクションを更新する
- **「商品案(初期)」トグルには絶対に触れない**（読み取り専用。変更は商品企画セッションの管轄）

## フィードバックログ
