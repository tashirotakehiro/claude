# Notion運用ルール（商品企画スキル共通）

## 保存先
- **企画ページ**: プロジェクトDBのテンプレート「【新商品】企画定型（新ルール）」で作る。1企画＝プロジェクトDBの1ページ（`notion-template.md` 参照）
- **調査履歴**: 企画ページの「5.販売価格」直下の子ページ。企画に至るまでの調査と経緯の置き場
- **需要調査ページ・アイデア3案ページ**: 企画ページができる前の工程なので、田代メモ (115b9edd0d8280d4abb2e0b6fbfee593) 直下に「需要調査: <テーマ>（YYYY-MM-DD）」「アイデア3案: <テーマ>（YYYY-MM-DD）」として作る。企画ページを作ったら調査履歴からリンクする
- **フィードバックログ**: 田代メモ直下の「商品企画フィードバックログ」

## 調査結果のURL報告（毎回必須）
- 調査を実行したら、結果を Notion に書き、**そのページの URL をチャットで送る**。チャットは要約＋URL
- 書き込みの直後に送る。既存ページを更新した場合も、更新したページの URL を送る

## 分割書き込み（タイムアウト防止）
- 長文は1回で書かず、ページ作成 → 追記で3〜5回に分ける。1回3セクション程度

## 調査履歴（企画ごとの調査の記録）
人が普段読むページではなく、後から「なぜこの形になったか」をたどるため、そしてマーケ調査が前提を読み直すための記録。チャットの要約ではなく、ここを読み直す。
- **作成タイミング**: 企画ページを作るとき（product-planning Step 4）
- **セクション構成**:
  1. **需要**: 狙った悩み、需要調査ページへのリンク、需要の確からしさの要点
  2. **アイデア**: アイデア3案ページへのリンク、選んだ案と見送った案（理由）
  3. **形を詰めた経緯**: 決まった構造、検討して採用しなかった方式とその理由、オーナーの指示（言葉のまま）
  4. **画像**: 作った画像の一覧（Notion に上げたもの）。古い構図のものはそう書く
  5. **懸念と未確認事項**: 売れないと思う理由・弱点、試作や確認が必要なこと
- 書き方は `writing-style.md` の密度。出典は末尾の「根拠・出典」トグル

## 商品企画フィードバックログ（スキルを跨いだ学習の仕組み）
- 1判定＝1行の箇条書きで追記する:

  `[YYYY-MM-DD] テーマ | 案名 | フック(30字) | ステージ | 判定 | 理由`

  - ステージ: 悩みの選定 / アイデア選定 / 形の確定 / マーケ調査 / 発売後
  - 判定: 採用 / 見送り / 没 / ヒット / 不発（**判定するのは常にユーザー**）
  - 理由: ユーザーの言葉をなるべくそのまま残す（**最重要フィールド**）

### 読み込み（product-idea・market-research が実行前に行う）
1. ログの直近30件を読む
2. 没・見送りの理由から避けるパターン、採用・ヒットから勝ちパターンを拾う
3. チャットの冒頭で「今回避けること」を1〜2行で伝え、案づくりに反映する
4. ログが無い・空ならスキップ

### 書き込み
- ユーザーの判定（採用/見送り）が出た直後に1行追記する
- 見送りの理由が分からなければ一言だけ聞く（しつこく聞かない。もらえなければ「理由未記録」）
