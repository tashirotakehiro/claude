# Notion 企画ページの作り方（商品企画スキル共通）

商品企画の成果物は、プロジェクトDBのページテンプレート **「【新商品】企画定型（新ルール）」** で作る1ページ。このファイルはその型・書く欄・書き方・作成手順の単一仕様書。書き方の密度は `writing-style.md` に従う。

## 保存先とID
- **プロジェクトDB（データソース）**: `collection://174b9edd-0d82-815d-a28c-000b1b069e30`（名称「プロジェクト」／くDB配下「商品企画管理」内）
- **テンプレート**: 「【新商品】企画定型（新ルール）」`3f9b9edd0d828069871df833ef16a6a5`（開発ボードはこのページから取り込む。表の項目名は変えない）
- タイトルプロパティは **`プロジェクト名`**、ステータスは **`ステータス`**（status 型）

## ページの構造（テンプレートの並び）
```
（次にやること のコールアウト）
### 商品名（仮）：
▸ 商品案(初期)                        … トグル
**1.開発コンセプト(…)：**              … ここに画像を貼る
**2.主な機能・性能(…)：**
**3.顧客のメリット(…)：**
**4.想定ターゲット(…)：**
  （ここに 4-1.懸念 と 根拠・出典トグル を足す）
▸ 競合商品(…)：                       … トグル（商品1〜3）
**5.販売価格：**                       … 書かない
  └─（ここに「調査履歴」子ページを置く）
▸ マーケ調査                           … 書かない（my-marketing-research の担当）
▸ 確認会の評価／確定した商品概要／必要仕様／キックオフ共有事項 … 書かない（人が後で書く）
目次 / 議事録
```

## 商品企画スキルが書く欄
| 欄 | 書く内容 |
|---|---|
| 商品名（仮）： | 名前（仮）｜ひとことで何か |
| 商品案(初期) トグル | 決まった仕様を箇条書きで1項目1行（コンセプト・場面・構造・使い方・付属・安全・重さ目標 等）。生きたドキュメントとして更新する |
| 1.開発コンセプト | コンセプトと**なぜ売れそうか**。下に画像1〜2枚 |
| 2.主な機能・性能 | 仕組み（形・構造・方式）と使い方 |
| 3.顧客のメリット | 「〇〇によって△△できる」の形で5行以内 |
| 4.想定ターゲット | 軸の一言＋A〜Dのペルソナと評価 |
| 4-1.懸念（売れないと思う理由・弱点） | 4 の直後に足す。判定ではなく材料 |
| 根拠・出典（1〜4） | 4-1 の直後に足すトグル。本文から外した出典・数字・確信度 |
| 競合商品 トグル | 最も近い競合3品（テンプレートの形のまま） |
| 5.販売価格 | **書かない**（価格は人が決める） |

## 各欄の書き方（見本）
テンプレートの「例：…」の行は消してから書く。見出しの文言は変えない。

```
**1.開発コンセプト(何を目的とした商品なのか)：**
- **どこでも、頭ひとつぶんの個室をつくる**
- 知らない人の隣でも、無防備な顔をさらさず眠れる
	- 機内・新幹線・夜行バス・オフィス・山小屋で使う
- なぜ売れそうか
	- [（需要の数字や、すでに払っているお金を1行）](根拠のページのURL)
	- [（競合に無い形を1行）](根拠のページのURL)
![（形の名前）](file-upload://…)

**2.主な機能・性能(どのように目的を達成するのか)：**
- **首支えの襟から、幌のようにフードが広がる**
	- 耳の位置の軸から、細いアーチ3本が前に開く
- 座り：顔から手元までを囲い、中でスマホが使える
- **畳むとアーチが襟に重なり、厚手の襟だけになる**

**3.顧客のメリット(購入した人は何ができるようになるのか)：**
- **幌のフードによって、寝顔を見られずに眠れる**
- 首支えによって、座ったまま頭が落ちずに眠れる

**4.想定ターゲット(誰の悩みを解決するのか)：**
- 軸：「知らない人のすぐ隣で眠るしかない人」
	- A. **長距離便で寝顔をさらしたくない旅行者**：◎本命
	- B. 山小屋の相部屋で光と気配に眠れない登山者：○対抗
	- D. 職場の人に寝顔を見られたくない会社員：△フックだけ
	- 外す：画面の覗き見だけ気になる人（フィルターで足りる）
**4-1.懸念(売れないと思う理由・弱点)：**
- **（いちばん大きい懸念を1行）**
- （使う回数・目立つ・作れるか・似た商品に見える 等を1行ずつ。4行まで）
<details>
<summary>根拠・出典（1〜4）</summary>
	- （出典・数字・確信度・推定の式を1行ずつ）
</details>
```
- ペルソナの評価は ◎本命 / ○対抗 / △フックだけ / 外す（my-marketing-research と同じ）。本命は1〜2個
- 「なぜ売れそうか」は需要調査の数字・お金を払っている行動・競合に無い形のどれかに結びつける。根拠の無い期待は書かない
- **「なぜ売れそうか」の各行には、根拠のページへのリンクを必ず貼る**（行の文字そのものをリンクにする。URL を並べない）
	- リンク先は、その数字や事実を自分の目で確かめられる一次のページ（Amazon の商品ページ・レビュー・統計・広告ライブラリ 等）
	- 一次のページが無い根拠（社内アプリの集計、複数ページを数えた件数）は、需要調査ページへリンクし、数え方は「根拠・出典」トグルに書く
	- リンクを貼れない根拠は「なぜ売れそうか」に書かない（密度チェックで NG になる）

### 競合商品トグル（テンプレートの形のまま埋める）
```
	- 商品1：（商品名）
		- URL：（リンク）
		- 価格：¥◯,◯◯◯
		- 機能：（形態をひとこと）
		- 差別化ポイント(他の商品と比較してこの商品を購入する理由)：（この企画がどこで勝つか、勝てないか）
```
- 3品は「この企画に一番近い形」から選ぶ。競合の地図全体は調査履歴のアイデア3案ページへのリンクで示す

## 作成・書き込み手順
1. **作成**: `notion-create-pages` で作る
   - `parent` は `{type:"data_source_id", data_source_id:"174b9edd-0d82-815d-a28c-000b1b069e30"}`
   - `pages[0].template_id` に `3f9b9edd0d828069871df833ef16a6a5`。`content` は渡さない
   - `pages[0].properties.プロジェクト名` に「名前（仮）｜ひとことで何か」
   - ⚠️ `notion-duplicate-page` は使わない（テンプレートの複製になり、DBの行一覧に出ない）
   - テンプレートの適用は非同期。`notion-fetch` で本文が揃ってから書く
2. **プロパティ**: `notion-update-page` の `update_properties` で設定する
   - `分類`＝`新商品`／`ステータス`＝`新商品ｱｲﾃﾞｱ`（半角カナ。以後変えない）
   - `提案者`＝田代剛大（`["eb081f10-9914-4ee2-b852-ce678af80065"]`。変わっていたら `notion-search` の user 検索で `tashiro.takehiro@survaq.com` を引く）
   - `企画作成日`＝当日（`date:企画作成日:start`、`date:企画作成日:is_datetime`＝0）
3. **下書きと密度チェック**: 1〜4・4-1 を `### 1.開発コンセプト` のような見出しで scratchpad に書き、`check_density.py` を NG 0 件にする（Notion には太字の見出しのまま書く）
4. **本文**: `notion-update-page` の `update_content` で、見出し直下の `<empty-block/>`（と「例：」の行）を置き換える
   - `old_str` は見出しの文言ごと含めて一意にする。トグル内はタブ付きなので fetch した実物をそのままコピーする
   - 1回3セクション程度、3〜4回に分ける
5. **画像**: `writing-style.md`「Notion に貼る」の手順でアップロードし、1.開発コンセプトの本文の下に貼る
6. **調査履歴**: `notion-create-pages`（parent＝企画ページ）で作ると末尾（議事録の下）に入るので、`update_content` で `<page url=…>` の行を「**5.販売価格：**」の直下へ移す（移動は1回の `update_content` で「末尾から消す」と「5.の下に足す」を同時に行う）
7. 最後に `notion-fetch` して、画像・4-1・根拠トグル・調査履歴の位置を確かめる
